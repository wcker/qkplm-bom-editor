# ADR-0002：Canvas 加 DOM 语义与编辑层

- 状态：已接受
- 日期：2026-07-18
- 规范依据：[v2 白皮书](../../现代化高性能可复用BOM编辑器组件.md)，重点参见第 6、10、13 章

## 上下文

目标数据规模达到 1 万至 10 万行，并支持树结构、冻结列、双向虚拟化、高频选区反馈和自定义单元格。为全部可见内容持续维护复杂 DOM 节点会增加布局、样式计算和垃圾回收压力，但纯 Canvas 缺少原生文本输入、焦点、表格语义和读屏能力。

视觉渲染、无障碍语义和实际输入属于不同问题。把三者塞进同一种节点模型，会在性能、输入正确性和 WCAG 2.2 AA 之间产生不必要的取舍。

## 决策

1. 主视觉渲染使用限定在视口、冻结区域和 overscan 内的三层 Canvas：低频背景层、内容层和高频交互层。三层表示失效频率隔离，不声明物理并行。
2. 行和列均执行虚拟化。局部变化优先使用 dirty rect；超过阈值后才提升为整层重绘。禁止创建与完整 10 万行等高的画布。
3. 同步维护有界、虚拟化的 DOM `treegrid` 语义层。它提供行列身份、层级、展开状态、选中状态、总量、当前位置和读屏播报，不负责复制整张视觉表格。
4. `treegrid` 使用 `aria-activedescendant` 管理浏览焦点。活动单元格滚出挂载区时，保留轻量语义代理或先移动活动项，禁止指向不存在的 DOM ID。
5. 文本输入和交互式编辑统一使用受控 DOM Portal。进入编辑时焦点移入真实输入控件；提交、取消、错误或卸载时按编辑状态机恢复焦点和视口锚点。
6. Canvas、语义 DOM 和编辑 Portal 必须消费同一份可见投影、稳定 `occurrenceId`、列 ID 和交互状态。DOM 层不得成为第二份领域数据源。
7. Canvas 命中测试基于统一逻辑坐标，显式转换 CSS 像素和设备像素。DOM overlay 数量、Canvas backing store 和缓存均纳入资源预算。
8. OffscreenCanvas 是可选增强，不是基础功能和无障碍路径的前提。

## 后果

### 正面后果

- Canvas 可控制重绘范围、节点数量和内存，适合大规模树表格的滚动与高频反馈。
- DOM 保留浏览器成熟的 IME、输入法、文本选择、焦点和无障碍生态。
- 语义层与视觉层解耦后，可以分别验证像素正确性和可访问性。
- 插件可分别扩展 Canvas renderer 与受控 DOM editor，而无需改变领域模型。

### 代价与约束

- 同一可见投影需要驱动三个呈现面，必须严格处理同步时序和稳定身份。
- 字体、缩放、DPR、RTL、冻结列和滚动偏移需要进入统一坐标契约，测试矩阵较大。
- DOM 语义代理和 Portal 焦点恢复增加状态机复杂度。
- Canvas 文本不会自动获得 DOM 的换行、选择和布局能力，需要明确测量与缓存策略。

## 被否决方案

### 全量 DOM 表格或树表格

否决原因：无法在目标规模下稳定约束节点、布局和样式计算成本，复杂冻结与高频交互也更难达到帧预算。

### 纯 Canvas，包括输入与无障碍

否决原因：无法提供可靠的原生 IME、文本编辑、焦点路径和 `treegrid` 语义，不满足可访问性门禁。

### 默认使用 WebGL 渲染全部内容

否决原因：文本清晰度、字体布局、context 恢复、资源复杂度和插件门槛更高，而当前目标尚不足以证明其收益超过 Canvas 2D。

### 为所有数据行保留隐藏 DOM 语义节点

否决原因：隐藏节点仍造成内存和可访问树成本，破坏虚拟化的资源上限。

## 验证方式

- 在固定 10K/100K fixture 上测量滚动帧、输入呈现延迟、DOM 节点上限、Canvas backing store 和销毁留存。
- E2E 覆盖纵横滚动、冻结列、缩放、DPR 变化、变量行高、字体迟到、RTL、触摸滚动和 context 恢复。
- 使用屏幕阅读器和自动化无障碍检查验证 `treegrid` 层级、活动单元格、选区、展开状态、行列位置和实时播报。
- 覆盖中文、日文和韩文 IME 的 composing、提交、取消、滚动、失焦、Tab 与 Esc 状态转换。
- 分别断言 Canvas 像素结果和语义 DOM，验证二者使用相同 `occurrenceId`、列 ID 和活动状态。
- 对 DOM overlay、语义代理和事件监听器执行挂载/卸载/销毁泄漏测试。
