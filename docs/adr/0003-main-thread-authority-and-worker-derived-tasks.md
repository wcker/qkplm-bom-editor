# ADR-0003：主线程权威模型与 Worker 派生任务

- 状态：已接受
- 日期：2026-07-18
- 规范依据：[v2 白皮书](../../现代化高性能可复用BOM编辑器组件.md)，重点参见第 2、7、8、14 章

## 上下文

文件解析、检索索引、批量校验、结构 Diff 和大规模计算可能超出单帧预算，适合移出主线程。但 UI 命令需要同步读取一致 Snapshot，并在模型、索引、可见投影和 revision 之间完成原子提交。

若主线程和 Worker 都能独立提交领域状态，消息延迟、任务取消、Worker 崩溃和多实例竞争会形成双写与脑裂。若所有任务都留在主线程，则目标规模下无法稳定保证输入响应。

## 决策

1. 主线程 headless model 是当前文档规范 Snapshot、revision 和提交历史的唯一权威来源。
2. Worker 只执行任务局部计算或维护带版本戳的派生副本。Worker 可以返回候选 Snapshot、诊断、索引、Diff 或 Patch 提案，但不能直接提交领域状态、递增本地 revision 或触发外部副作用。
3. 每个任务必须携带 `protocolVersion`、`instanceId`、`taskId`、`documentId`、`documentGeneration`、`documentRevision`、优先级和取消信息。主线程在接受结果前重新核对协议、generation 和 revision；过期结果只结算为取消/过期并记录指标，不得写入当前文档。
4. Worker 结果若会改变文档，必须回到主线程经过 Schema、结构不变量、权限策略和业务规则校验，再作为原子事务提交。
5. 默认使用有界共享 Worker 池，以实例配额和公平调度实现逻辑隔离；只有调用方明确配置时才创建独占 Worker。
6. Worker Runtime 必须实现取消、超时、背压、任务合并、公平性、崩溃检测和重建。仅纯函数、幂等、输入 revision 未变化且没有进入提交阶段的任务可以自动重放。
7. Worker 不可用、URL 失败或 CSP 阻止时，对允许的任务使用可取消、可让步的主线程分片；正确性、原子性和安全校验不得降级。
8. Transferable 仅用于任务专属派生缓冲或显式原子迁移的所有权。仍被权威 Snapshot 引用的缓冲区禁止转移并 detach。

## 后果

### 正面后果

- 领域状态只有一个提交点，便于保证原子性、事件顺序和确定性 Undo/Redo。
- 重计算可以并行且可取消，不阻塞高优先级输入和绘制。
- Worker 崩溃、迟到消息和文档替换不会污染当前 Snapshot。
- 共享池限制线程和内存总量，并能对多实例进行公平调度。

### 代价与约束

- 所有任务都需要版本信封、结果核验和序列化协议。
- 派生数据传输可能产生 clone、字典编码和临时内存成本，必须计入端到端指标。
- 主线程仍承担最终验证与原子提交，不能把提交成本错误地排除在性能报告之外。
- 无 Worker 环境需要维护功能等价的分片降级实现。

## 被否决方案

### Worker 作为领域模型唯一权威来源

否决原因：同步 `getSnapshot()`、UI 命中后的即时读取和原子事件时序都需要跨线程往返，输入路径复杂且容易出现状态闪烁。

### 主线程与 Worker 双权威

否决原因：无法在崩溃、取消、迟到结果和并发提交下可靠避免 revision 分叉与丢失更新。

### 每个编辑器实例固定创建独占 Worker

否决原因：多实例时线程、Heap 和初始化成本线性增长，不能保证资源预算和实例公平性。

### 所有计算留在主线程

否决原因：文件解析、100K 索引和批量规则会制造长任务，破坏输入和滚动 SLO。

### 自动重放所有失败任务

否决原因：事务提交、文件写出和外部调用可能产生重复副作用，违反幂等性与审计要求。

## 验证方式

- 属性测试验证任意 Worker 结果顺序、重复、延迟和取消组合都不会改变不匹配 revision 的 Snapshot。
- 故障注入覆盖 Worker 启动失败、协议不匹配、运行时崩溃、超时、消息重复、迟到结果和重建。
- 文档替换和实例销毁测试验证旧 `documentGeneration` 的任务无法产生数据事件或保留实例引用。
- 多实例基准报告共享池队列延迟、公平性、Heap、取消延迟和输入 P95/P99。
- 在禁用 Worker 和受限 CSP 环境运行等价正确性套件，并验证主线程分片能够让步和取消。
- 对所有可写 Worker 结果执行“主线程重新验证后提交”契约测试，确认 Worker 无法直接递增 revision。
