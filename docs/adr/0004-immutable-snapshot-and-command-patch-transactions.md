# ADR-0004：不可变 Snapshot 与 Command-Patch 事务

- 状态：已接受
- 日期：2026-07-18
- 规范依据：[v2 白皮书](../../现代化高性能可复用BOM编辑器组件.md)，重点参见第 3、4、8、16 章

## 上下文

BOM 编辑同时涉及领域节点、结构索引、搜索索引、计算缓存、可见投影、历史记录和事件。允许调用方原地修改对象，或让不同模块分别更新各自状态，会暴露半提交结果并使 Undo、审计、远程同步和缓存失效无法确定。

调用方表达的是“把节点移动到某位置”“设置某字段”等意图，而跨进程同步和审计需要稳定、可序列化的具体操作。用同一种结构同时承担用户意图与传输日志，会泄露 `positionKey` 等内部机制或丢失并发前置条件。

## 决策

1. `BomDocumentSnapshot` 是只读、版本化、可确定性序列化的领域状态。`getSnapshot()` 不暴露内部可变索引、缓存或对象；任何状态改变都必须产生新的 revision。
2. 普通调用方通过 `BomCommand` 表达意图，使用稳定 `occurrenceId` 和 `BomPlacement`，不得依赖可见行下标或自行生成内部排序键。
3. Core 在当前 Snapshot 上校验 Command，并编译为带 `protocolVersion`、`documentId`、`baseRevision`、`transactionId`、`origin`、有序 operations 和可选幂等键的 `BomPatch`。
4. Patch 是传输、审计、Diff 和回放协议。外部 `applyPatch()` 只接受受信兼容来源，并仍需验证协议、文档、base revision、操作格式、排序键、Schema 和结构不变量。
5. 事务按“准备 -> 校验 -> 原子提交 -> 事件”执行。领域 Snapshot、基础索引、可见投影、相关缓存和 revision 必须一次切换；任何步骤失败均不得暴露部分更新。
6. 每个可撤销事务生成逆操作或可恢复检查点。Undo/Redo 通过事务路径执行，完成后重新验证不变量和规范 Snapshot 哈希。
7. 不可变语义不要求每次深拷贝完整文档。内部可以使用结构共享、copy-on-write、持久化数据结构和增量索引，但共享节点一经发布不得再修改。
8. 字段路径必须由 Schema 解析并阻止危险键。可选 `expectedValueHash` 提供字段级乐观检查，但不能代替文档 `baseRevision`。
9. 粘贴、拖拽、批量编辑、导入和已批准修复默认各形成一个全量成功或全量回滚的事务；部分成功必须显式启用并返回实际 Patch。

## 后果

### 正面后果

- 每个 revision 都对应稳定 Snapshot，可安全供渲染、插件、Worker 和审计读取。
- Command 隐藏内部排序和协议细节，Patch 则提供确定的跨边界表示。
- 原子提交使索引、视图和数据不会出现短暂不一致。
- 逆操作、规范哈希和版本化 Patch 使 Undo/Redo、远程同步和故障恢复可验证。

### 代价与约束

- 需要设计结构共享和增量索引，避免不可变语义导致 100K 数据的全量复制。
- Command 与 Patch 需要分别维护版本、迁移和契约测试。
- 插件不能直接修改对象，必须注册命令处理器或返回提案。
- 历史记录必须同时受条目和字节预算约束，大事务需要检查点策略。

## 被否决方案

### 暴露可变行对象供调用方直接修改

否决原因：Core 无法可靠检测变更、验证不变量、生成审计 Patch 或同步失效缓存。

### 只使用 Command，不保留 Patch

否决原因：意图命令依赖执行上下文，不能直接作为确定的同步、审计和逆操作协议。

### 只公开底层 Patch，调用方自行构造

否决原因：会泄露 `positionKey`、rebalance 和并发细节，普通调用方容易制造非法结构或不兼容协议。

### 每次事务深拷贝整个 Snapshot

否决原因：时间、内存和 GC 成本随总行数增长，不符合目标规模和历史预算。

### 先更新模型，再异步修复索引和视图

否决原因：会向读取方暴露同一 revision 下互相矛盾的状态，也无法实现可靠回滚。

## 验证方式

- 属性测试随机生成命令序列，逐次比较增量索引与从 Snapshot 全量重建的结果。
- 对每个可撤销命令验证 `apply(command) -> undo` 后规范 Snapshot 哈希与操作前一致，并验证 redo 的确定性。
- 契约测试覆盖错误 base revision、重复 ID、循环、孤儿、非法字段路径、无效排序键和 Patch 协议版本。
- 测试调用方尝试修改已返回 Snapshot 时不能影响当前 revision、索引或后续事件。
- 故障注入在准备、校验、索引更新和事件前各阶段抛错，验证不会暴露半提交文档。
- 基准记录单字段更新、子树移动、批量粘贴和大型导入的耗时、分配量、结构共享率与历史字节数。
