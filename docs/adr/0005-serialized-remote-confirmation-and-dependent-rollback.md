# ADR-0005：远程事务串行确认与依赖回滚

- 状态：已接受
- 日期：2026-07-18
- 规范依据：[v2 白皮书](../../现代化高性能可复用BOM编辑器组件.md)，重点参见第 4、8、14 章

## 上下文

为了保持编辑响应，本地命令需要在服务端往返前应用；但服务端以独立的 `sourceRevision` 验证写入。同一文档连续产生多个本地事务时，后续事务可能建立在尚未确认的前序结果之上。

若并行发送这些 Patch，它们会携带相同或无法确定的远程基线，确认顺序也可能与本地顺序不同。若父事务被拒绝后只应用父事务的 inverse Patch，仍然生效的后代可能引用已不存在节点、旧字段或错误位置，导致结构损坏或用户编辑丢失。

## 决策

1. 本地事务先在主线程原子应用，并进入 `localApplied -> pending`。`transactionCommitted` 只表示本地成功，远程持久化状态由独立事件报告。
2. 同一文档允许连续本地提交，但向 writable DataSource 的远程提交严格 FIFO 串行。队首事务使用最近已确认的 `sourceRevision`；只有其 acknowledged 后，下一事务才能发送。
3. 未发送后续事务通过 `dependsOnTransactionId` 形成有序依赖链。所有远程 Patch 必须包含全局唯一 `idempotencyKey`，重试不得创建新的逻辑写入。
4. acknowledged 只推进持久化状态和 `sourceRevision`，不得再次应用已经在本地生效的 Patch。
5. rejected 默认触发系统来源的原子依赖回滚。Runtime 暂停父事务的全部后代，按逆序回滚后代，再回滚父事务；禁止在后代仍生效时直接应用父事务 inverse Patch。
6. conflicted 进入调用方配置的拒绝、重载或三方变基流程，禁止静默 last-write-wins。
7. 回滚后，可以在隔离 staging model 中按原 Command 顺序整体重放/变基后代。只有全部校验通过才一次性恢复；否则保留版本化 `RecoveryBundle`，包含足够的命令、基线和冲突诊断供用户或宿主恢复，禁止静默丢弃编辑。
8. pending 事务的 Undo 由 DataSource 能力决定取消原提交或排入依赖性补偿 Patch。两种路径均须幂等并产生可审计事件。
9. 远程订阅 envelope 按源端 `sequence` 和 source revision 验证，再转换成以当前本地 revision 为基线的新本地 Patch。序号缺口、revision 不连续或未知协议必须停止增量应用并触发 resync。
10. 回滚、重放、变基、补偿和恢复事件都关联原 transaction ID，同时携带当前本地 revision 与 source revision。

## 后果

### 正面后果

- 本地编辑保持即时响应，服务端仍获得严格的 revision 前置条件。
- 远程写入顺序与本地依赖顺序一致，降低冲突和重复副作用。
- 拒绝父事务时可以恢复到结构一致的基线，并显式保护后续用户编辑。
- 本地 revision 与 source revision 的含义清晰，事件和审计可追踪。

### 代价与约束

- 单文档远程写吞吐受一次只发送一个事务限制；高延迟链路会增加 pending 队列。
- Runtime 需要保存未确认命令、逆操作、依赖关系和恢复数据，受内存预算约束。
- 冲突处理、staging 重放和恢复 UI 明显增加实现与测试复杂度。
- 跨实例实时协作仍需要服务端顺序与冲突协议，本决策本身不等同于 CRDT。

## 被否决方案

### 并行提交同一文档的远程 Patch

否决原因：多个事务无法可靠共享同一 expected source revision，乱序确认会破坏依赖和审计顺序。

### 等待服务端确认后才应用本地编辑

否决原因：交互延迟直接受网络控制，不满足高响应编辑体验，也不能离线工作。

### 父事务失败时只回滚父事务

否决原因：后代可能依赖父事务创建或移动的结构，直接反转父项会产生悬空引用和错误 inverse。

### 冲突时静默采用最后写入覆盖

否决原因：会无提示丢失本地或远程编辑，不符合工业数据正确性和审计要求。

### 后代重放失败时直接清空 pending 队列

否决原因：用户已经完成的编辑会不可恢复地丢失，且故障无法审计。

## 验证方式

- 使用可控 DataSource 模拟延迟、重复响应、断线和重试，断言任意时刻同一文档最多一个远程 commit in-flight。
- 模型测试覆盖 acknowledged、rejected、conflicted、取消、pending Undo 和补偿 Patch 的全部状态转换。
- 随机生成父子依赖链，在任意节点注入拒绝，验证逆序回滚后结构不变量和 Snapshot 哈希正确。
- 对后代重放分别注入全成功、字段冲突、节点缺失和规则失败，验证原子恢复或生成完整 `RecoveryBundle`。
- 模拟远程订阅重复、乱序、序号缺口、revision 跳变和未知协议，验证幂等、停止应用和 resync。
- 审计契约测试确保每个确认、回滚、变基、补偿和恢复事件都能关联原 transaction ID，且不包含敏感字段原值。
