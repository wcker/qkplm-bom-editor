# ADR-0006：生成式 AI 作为可选插件

- 状态：已接受
- 日期：2026-07-18
- 规范依据：[v2 白皮书](../../现代化高性能可复用BOM编辑器组件.md)，重点参见第 0、2、9、11、12、14 章

## 上下文

自然语言生成 BOM、字段补全和结构重构可能提高复杂编辑效率，但它们依赖模型供应商、网络、费用、隐私政策和非确定性输出。不同企业对数据出域、审计、模型部署和自动化授权的要求差异很大。

Core 的职责是提供确定、可撤销、可验证的通用编辑能力。把生成式模型调用内置到 Core，会让无 AI 场景承担包体积、网络和合规成本，也容易把概率性建议误当成结构不变量或可信事务。

## 决策

1. 生成式 AI 不进入首版 Core 必交付范围，以独立可选包 `@bom-editor/ai` 或等价插件交付。未安装、未注册 AI 插件时，Core 的类型、功能、性能和测试必须完整成立。
2. AI 插件通过公开 headless 插件 ABI 和宿主注入的 `AiProvider` 接入。Core 不绑定模型厂商、云端地址、凭据、SDK 或传输协议。
3. AI 只生成版本化提案，不直接修改 Snapshot。提案至少携带 `proposalId`、`baseRevision`、能力类型、影响范围、解释、置信度/不确定性、候选 Command 或 Patch 预览、模型与提示模板版本，以及经过脱敏的审计元数据。
4. 提案在应用前必须核对当前 revision，并由主线程重新执行 Schema、结构不变量、编辑策略、业务规则和安全校验。过期提案必须重新生成或显式变基，不得直接套用。
5. 默认要求用户确认。只有宿主显式配置、限定规则与影响范围且授权通过时，才允许自动批准低风险提案；最终变更始终形成单一、可撤销、可审计事务。
6. 循环结构、物料身份、数量、单位、父子关系和批量删除等高风险修改禁止后台静默应用。结构化预览必须显示实际 Diff 和受影响节点。
7. 数据最小化是默认策略。发送给 Provider 的字段由宿主白名单选择；凭据不得进入 Snapshot、Patch、日志、遥测或 Worker 消息。插件必须支持取消、超时、限流、费用上限和审计钩子。
8. 确定性结构规则、传统匹配和可重复业务规则继续由 Core/规则插件承担，不调用生成式模型。AI 失败、离线或被禁用不得降低基础校验与编辑能力。
9. AI 插件可以在 Core 合同稳定后独立演进，其 ABI、提案 Schema 和 Provider 协议均需独立版本化。

## 后果

### 正面后果

- Core 保持轻量、确定、离线可用，不强制数据出域或引入模型供应商锁定。
- 企业可以按隐私、部署和成本要求选择云端、本地或代理 Provider。
- AI 输出沿用 Command-Patch、预览、事务、Undo 和审计机制，不建立旁路写入通道。
- AI 能力可以独立发布和试验，不阻塞编辑器正确性内核与首版交付。

### 代价与约束

- AI 插件需要维护 Provider 抽象、提案协议、版本兼容和独立安全评审。
- 生成、预览、确认、重校验增加一次用户流程和端到端延迟。
- 置信度不能被视为真实概率保证，仍需带标注数据评估误改风险。
- 宿主必须明确字段白名单、授权策略、审计留存和费用边界。

## 被否决方案

### 在 Core 中内置指定大模型 SDK

否决原因：引入供应商锁定、包体积、凭据、网络、CSP、隐私和供应链风险，且破坏离线与按需能力边界。

### 允许模型直接返回并静默应用完整 Snapshot

否决原因：无法可靠解释最小变化、检查 stale revision、执行细粒度授权或提供可审计逆操作。

### 将 AI 输出当作结构规则结果

否决原因：生成式输出非确定且可能产生幻觉，不能替代唯一 ID、无环、Schema 等强制不变量。

### 永久排除生成式 AI

否决原因：自然语言生成、辅助映射和复杂重构具备产品价值，公开插件 ABI 可以在不污染 Core 的前提下承载它们。

### 默认上传完整 BOM 以提高上下文

否决原因：违反数据最小化原则，扩大商业敏感信息泄露、费用和上下文注入风险。

## 验证方式

- 构建和 E2E 验证在未安装 AI 包、离线和 CSP 禁止外连时，Core 全部基础能力正常且默认包不包含模型 SDK。
- Provider 契约测试覆盖取消、超时、限流、鉴权失败、流式中断、畸形输出和重复响应。
- 安全测试验证字段白名单、凭据隔离、日志脱敏、提示注入边界和禁止完整 BOM 默认出域。
- 对提案注入 revision 变化、节点删除、字段冲突、非法环和权限拒绝，验证不会绕过主线程事务校验。
- 每个已应用提案必须能够 Undo，并在审计中关联 proposal ID、transaction ID、模型/模板版本和用户或宿主批准来源。
- 使用带标注 fixture 报告提案接受率、错误修改率、撤销率和高风险误改数；只测响应时间不能作为发布依据。
