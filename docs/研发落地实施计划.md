# BOM 编辑器研发落地实施计划

> 状态：执行基线（Draft for Execution）  
> 唯一规范源：根目录《现代化高性能可复用BOM编辑器组件.md》v2.0  
> 配套追踪：[需求追踪矩阵](./需求追踪矩阵.md)  
> 适用范围：`@bom-editor/*` 正式发布包、Demo、基准、测试与发布工程

## 1. 执行原则

1. 白皮书 v2.0 是需求、架构和验收的唯一规范源。其他白皮书仅可作为历史背景，不得覆盖本计划或需求矩阵。
2. 正确性优先于性能。领域不变量、事务原子性、确定性 Undo/Redo 和安全边界未通过门禁时，不进入性能优化阶段。
3. Contracts First。所有跨包、跨线程、插件和持久化协议先形成可编译的公开类型、版本字段和契约测试，再实现运行时。
4. 以纵向切片驱动集成。首个可运行版本必须走公开 API，完成“10K 加载、Canvas 显示、选择、DOM 编辑、事务提交、Undo”闭环。
5. 性能结论只接受固定环境、固定 fixture、生产构建和机器可读报告；开发机手工观察只用于诊断。
6. 框架适配器保持薄层。Vue、React、UMD 不得复制 Core 的模型、事务、索引、调度或错误语义。
7. 每条规范通过稳定 REQ-ID 追踪。实现、测试、基准、ADR 和发布证据均引用 REQ-ID；ID 删除后保留为 retired，禁止复用。
8. 生成式 AI 不进入首版关键路径。自然语言生成 BOM、自动结构重构等能力在 GA 后通过可选 `@bom-editor/ai` 插件交付。

## 2. 目标仓库形态

以下路径是计划目标，实际创建前若需调整必须记录 ADR，并同步需求矩阵。

```text
  react/

  ai/                         # GA 后可选，不被 core 依赖

  demo-vanilla/
  demo-vue/
  demo-react/
benchmark/
  fixtures/
  baselines/
  reports/
  environment.json
tests/
  contract/
  property/
  e2e/
  accessibility/
  security/
  performance/
  soak/
docs/
  adr/
  compatibility/
  api/
```

包依赖必须保持单向：

```text
contracts
  <- model
  <- transaction / datasource / plugin-api-headless
  <- runtime
  <- renderer-canvas / plugin-api-browser

worker、import-xlsx -> contracts + model + 版本化协议
vue、react、umd     -> @qkplm/bom-editor 公开出口
ai                 -> 公开插件 ABI；core 不得反向依赖 ai
```

过渡期内，现有物理包 `@bom-editor/contracts` 是 contracts 类型的唯一实现来源；F0–F1 由稳定子路径 `@qkplm/bom-editor/contracts` 原样重导出，并通过 API 契约测试保证符号与语义一致。完成包内聚前不得复制协议类型形成第二套定义，物理迁移时必须使用 ADR 和兼容迁移方案。

## 4. 分阶段实施

### F0 规范与工程基座

交付物：

- 建立 workspace、统一 TypeScript 严格配置、生产构建、单元/属性/契约/E2E/基准命令。
- 建立公开出口和依赖边界规则，预留 DOM、WebWorker、Node/SSR 三组编译配置。

稳定 ID 顺序后，renderer 通过 `viewChanged(reason: 'columns')` 输出冻结几何。
顺序调整只更新受控视图，不产生文档事务、revision 或 Undo 记录；冻结切换、排序
筛选、多级表头和模板仍在后续切片。列显隐与宽度、顺序调整共享 `viewChanged` 的
`reason: 'columns'` 受控边界，不进入领域事务历史。

2026-08-09 Diff ghost-row 增量：`BomCanvasDiffView.ghostRows` 已完成 renderer/editor
闭环。宿主可按唯一删除稳定 ID、`start`/`end` 或当前行锚定的 `before`/`after` 位置，
并可选指定层级；ghost 行进入 Canvas、滚动高度、可见行位置和 ARIA 行计数/索引，但明确
只读、不可选择/编辑/展开且不能作为事务目标。renderer/editor 对重复 ID、当前 Snapshot
ID、未知锚点、非法层级和过期绑定均失败关闭；删除摘要 `deletedRows` 仍保留为不改变行计数
的 `role="note"` 表示。自动回归覆盖 DOM、位置、计数和输入隔离，人工读屏验收仍属于 F7/F8
发布门禁。

### F6 数据交换与安全

交付物：

- XLSX 异步模块与 CSV/TSV 流水线；XLS 保持可选适配器，不进入默认 Core。
- 导入阶段进度、取消、限额、字段映射、类型转换、Diff 预览和提交前 revision 复检。
- 当前视图、完整数据、可回导模板三类导出及其 `effectiveMode/lossless` 语义。
- Clipboard/Export/Edit/Plugin Grant Policy 的一致授权与不含原值的审计事件。
- HTML/URL 清洗、原型污染防护、ZIP bomb/资源耗尽防护、公式/宏/外链策略。
- 外部 Worker URL、严格 CSP、Trusted Types、遥测显式开启、命名空间存储、SBOM 和供应链门禁。

门禁：

- 取消、超时、Worker 崩溃、恶意文件或 `baseRevision` 冲突不改变当前文档。
- 未配置 Export Policy 时完整数据导出返回 `E_EXPORT_AUTH_REQUIRED`。
- 无损完整导出回导后结构、类型和规范值等价；Policy 变换不得标称无损。
- 兼容矩阵固定精确客户端 build、OS、fixture 哈希和逐能力结果。

### F7 适配器、无障碍与平台兼容

交付物：

- Vue 3、React 和 UMD 一对一映射 Core API、事件、错误、默认值和生命周期。
- 完整虚拟化 ARIA treegrid、DOM 编辑焦点转换、Live Region 和键盘结构移动。
- 可注入语言包、运行时 locale 切换、Intl、Unicode、双向文本与 RTL。
- 设计令牌、深浅主题、高对比、forced-colors、减少动效和缩放/Reflow。
- 精确浏览器、框架、TypeScript、bundler、Excel/WPS 版本矩阵及降级事件。

门禁：

- React StrictMode、Vue KeepAlive、UMD 重复挂载和多实例焦点切换通过共享契约测试。
- A 级平台完整任务集达到 WCAG 2.2 AA；B/C 级在声明范围内达到同一标准。
- NVDA、JAWS、VoiceOver 桌面人工任务通过；声明支持的移动端功能通过 VoiceOver/TalkBack。
- locale、主题和方向切换不丢失文档、历史、草稿、选区或视口锚点。

### F8 GA 发布鉴定

交付物：

- Vanilla、Vue、React Demo 共享 fixture 和公开 SDK 验收脚本。
- 固定 runner 的原始测量、P50/P95、满足样本量时的 P99、环境信息和通过/失败 JSON。
- 2 小时稳定性、故障注入、内存趋势、销毁残留和 1/3/5 实例报告。
- API、事件、错误码、DataSource、插件、CSP、无障碍、兼容与接入文档。
- v1.0 产品合同、支持矩阵、Preview/Beta/GA 声明边界，以及原生 HTML、Vue 3、React 的公开 SDK
  接入、恢复和销毁示例。
- `pnpm --filter @bom-editor/demo test:onboarding:browser` 连接固定 `4173` Demo、自动使用当前机器
  Chrome，并逐一验证 Native、React、Vue、UMD 的公开挂载、失败恢复和销毁重建路径。
- Changelog、API 差异、迁移指南、协议版本、已知限制、SBOM 和许可证清单。

门禁：

- `pnpm release:verify` 聚合运行类型、API、单元、属性、契约、E2E、安全、无障碍、性能和稳定性门禁。
- 白皮书 14.5 任一阻断项失败即停止发布；例外只允许白皮书明确可例外项且必须有未过期 ADR/风险接受记录。
- 对外优势描述逐项链接到同一构建哈希的基准、兼容或测试证据。

### F9 可选 `@bom-editor/ai`

范围仅包含生成式或远程模型能力，例如自然语言生成 BOM 草案、结构重构建议和规则解释。白皮书已有的确定性索引、匹配、校验和修复仍属于 Core/插件基础能力，不依赖生成式 AI。

约束：

- `@bom-editor/ai` 只能依赖公开插件 ABI、Command/Patch 和只读 Snapshot；禁止访问 Core internal。
- 默认不发送 BOM 内容；宿主必须显式配置服务、字段范围、脱敏、租户策略和用户授权。
- 模型输出只能形成带来源、模型版本、置信度、风险和结构 Diff 的建议，不得静默提交。
- 用户或宿主策略批准后，建议通过单一可撤销事务提交，并接受全部结构、Schema、业务和安全校验。
- 提供固定评测集，报告结构有效率、误改率、拒绝率、延迟、成本和数据外发审计；不得用演示样例代替验收。
- AI 包失败、离线或未授权时不得影响 Core 查看、编辑、导入导出和恢复能力。

## 5. 依赖与并行工作流

主依赖链为：

```text
F0 -> F1 -> F2 -> F3 -> F4 -> F8
                  |      |
                  +-> F5 +-> F7 -> F8
                       |
                       +-> F6 -> F7/F8

F8(GA) -> F9
```

可并行但必须遵守的边界：

| 工作流 | 可并行起点 | 不得提前冻结的内容 |
| --- | --- | --- |
| Canvas/交互 Spike | F1 开始后 | 公开 API、坐标 ABI、性能承诺 |
| Worker/搜索 Spike | F1 开始后 | Worker 协议和索引持久化格式 |
| 适配器壳层 | F3 API 候选稳定后 | 默认值、事件顺序和错误映射 |
| XLSX 安全研究 | F1 后 | 导入协议、Policy 和资源限额 |
| 无障碍原型 | F3 前可探索 | treegrid 焦点模型必须在 F3 门禁冻结 |
| AI 研究 | GA 前可离线评估 | 不进入 Core、不阻塞 F0–F8、不接触真实 BOM 数据 |

## 6. 统一质量门禁

每个 REQ 只有同时满足以下条件才可标记“已验证”：

1. 代码仅通过公开依赖边界实现，类型和协议版本已落地。
2. 正向、失败、取消、过期和资源释放路径具备测试；测试名或报告引用 REQ-ID。
3. 相关 API Extractor、协议 fixture 和迁移策略已更新。
4. 性能敏感项提供固定 fixture 的原始样本和环境，不只提供平均值或截图。
5. 安全、隐私、可访问性和兼容性影响已评估；需要人工验证时归档签字结果。
6. 文档、Demo 和适配器均通过公开 SDK，不读取 internal 状态。
7. 存在例外时，ADR 包含责任人、证据、影响、回退路径和到期条件。

计划统一提供以下顶层命令，具体 runner 参数由 F0 固化：

```text
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:property
pnpm test:contract
pnpm test:e2e
pnpm test:a11y
pnpm test:security
pnpm benchmark
pnpm test:soak
pnpm release:verify
```

当前 F3 证据子集已经提供以下根命令：

```text
pnpm check:api
pnpm api:update
pnpm test:e2e:f3
pnpm benchmark:f3:browser
pnpm verify:f3
```

`check:api` 对比 8 个稳定 Core 入口的 API Extractor 报告并阻止漏导出/显式 `any`；`api:update` 仅生成待评审的新基线。`verify:f3` 聚合工作区检查和 formal 浏览器 runner，在当前未完成的资格条件下预期返回非零，不能通过跳过失败项改写为阶段准出。

## 7. 风险与控制

| 风险 | 早期信号 | 控制措施 | 最迟决策点 |
| --- | --- | --- | --- |
| 100K 内存被 Snapshot、索引和 Worker 副本放大 | F1 fixture 的字节模型超预算 | 结构共享、紧凑派生数据、任务专属 Transferable、缓存双预算 | F2 结束 |
| 可见投影局部操作退化为全数组复制 | 展开/移动耗时随 v 线性增长 | F4 前完成数据结构 Spike，并以复杂度/基准选型 ADR 固化 | F3 结束 |
| Canvas 与 ARIA 状态漂移 | 像素命中和活动 DOM ID 不一致 | 共享布局快照；Canvas 与语义 DOM 分别断言同一 revision | F3 结束 |
| IME、失焦与异步校验产生重复提交 | 状态机出现并发 committing | 单一显式编辑状态机、AbortSignal、状态模型测试 | F3 结束 |
| 远程拒绝导致依赖事务丢失 | 后代事务无法重放 | 串行提交、逆序回滚、staging rebase、RecoveryBundle | F2 结束 |
| 插件破坏帧预算或资源释放 | draw 超时、卸载后注册仍增长 | 能力授权、超时/隔离、自动登记和逆序清理 | F5 结束 |
| 文件解析导致内存峰值或拒绝服务 | 解压/共享字符串阶段陡增 | 分阶段计量、硬限额、Worker、取消、恶意 fixture | F6 结束 |
| 框架适配器语义分叉 | 同操作事件/错误不同 | 共享契约测试；适配器禁止业务逻辑 | F7 结束 |
| AI 扩大数据外发和误改风险 | 未经授权发送字段或直接提交 | 独立可选包、显式授权、Diff 建议、人工确认、审计 | F9 发布前 |

## 8. 变更控制

- 白皮书 v2.0 修改后，先更新需求矩阵的来源映射和影响分析，再调整计划；不得反向用实现现状改写规范含义。
- REQ 文本可澄清但 ID 不变；语义发生不兼容变化时新增 ID，并将旧 ID 标记 retired。
- 阶段门禁、包边界、SLO、兼容等级和协议主版本的变化必须提交 ADR。
- 阻断项不得通过删除测试、降低样本量、改变 fixture 或把失败场景移出报告来规避。
- 每次里程碑评审输出：已验证 REQ、未完成 REQ、风险、性能趋势、协议/API 差异和下一阶段准入结论。
