## 1. 使用规则

- ID 格式为 `REQ-<白皮书章号>-<三位序号>`。ID 一经分配永久稳定；删除需求时标记 `retired`，禁止复用或重排。
- 一个 REQ 只有在实现、自动化/人工证据、文档和适用发布门禁全部完成后才可标记“已验证”。“已实现但未验收”使用“待验证”。
- PR、提交、测试名称、基准报告、ADR 和发布说明必须引用相关 REQ-ID。
- “实现归属”表示负责提供行为的包或工程，不表示可以跨越白皮书规定的依赖边界。
- “验收证据”引用第 3 节测试目录；括号中的条件是该需求独有的断言，不可只运行空测试套件。
- P0 是首个纵向切片或正确性/安全基础的阻断项；P1 是 GA 必交付；P2 仅用于明确的 GA 后可选能力。
- 阶段 `F0–F9` 的定义以《研发落地实施计划》为准。

## 7. 维护检查

REQ-10-003 增量校正（2026-08-11）：多范围 `Delete`/`Backspace` 已不再 fail-closed。编辑器会对每个矩形执行可编辑性、Schema、当前值哈希和选区代际预检，按稳定 `(type, occurrenceId, fieldPath)` 去重并受总行数/单元格限额约束，最终以单一可 Undo 的 `editor:delete` 事务原子提交；任一失败保持 Snapshot 不变。DOM Portal 的 `Ctrl/Command+Enter` 支持多个至少两行、同一可编辑列的不连续矩形，按稳定 occurrence ID 去重后以单一 `editor:fill-selection` 事务提交；treegrid `Ctrl/Command+D` 也支持多个矩形，各自从首行向下填充并以单一 `editor:fill-down` 事务提交，冲突重叠整批拒绝。轴选区、跨列范围和复制/粘贴仍 fail-closed。
